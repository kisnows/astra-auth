# 认证与数据契约

本文件是独立认证服务的职责、身份兼容和发布契约。实现细节以 src/server 和 scripts 为准。

## 身份和接入

- Auth 拥有用户、凭证、认证会话、OAuth Client、授权配置和认证审计。业务数据归各接入应用。
- 通过公开 issuer + sub 标识统一身份。每个应用使用独立客户端、服务端密钥和精确回调地址。
- 授权码流程使用 S256 PKCE、state 和 nonce；授权码一次性消费，校验 issuer、audience 与签名。
- 新客户端默认拒绝访问，以明确的用户 ID 开放。authorize、token、userinfo 均检查应用授权。
- 认证管理员角色不会自动授予外部应用业务管理权限；客户端仍需执行自己的权限与数据范围校验。
- 应用保留自己的业务主体，通过显式绑定关联统一身份；同名邮箱不足以合并已有账号。
- Cookie 名与现有部署兼容，各系统独立持有会话。单站退出与全局退出须按明确协议实现。
- 内部服务接口沿用 HMAC 签名、方法、路径和时间窗口校验；仅通过服务器调用。
- 登录或授权校验失败时拒绝访问，不因 Auth 不可达自动授予权限。
- 机密 OIDC 客户端可在授权码兑换后持有轮换 refresh token；它只续期原客户端、用户和已批准 scope，最长 30 天，不滑动延长授权期限。每次续期复核当前应用授权、用户状态和客户端密钥版本。
- refresh token 仅存 SHA-256 摘要；消费、轮换与关联 access token 在同一写事务内处理。重放已消费令牌或明确撤销时，整条授权链失效；续期不代表可绕过用户禁用、应用撤权或强制改密。
- 现有 access token 和客户端继续兼容；新增表、可空 grantId 与版本化 bootstrap 迁移保留旧镜像回滚窗口。

## 第三方身份

- GitHub/Google 可根据稳定身份与上游已验证邮箱，在事务内注册普通账号。已有邮箱要求登录原账号后显式绑定。
- 微信网站扫码与通用 OIDC 使用已有账号绑定流程；原生小程序身份接入不属于本次仓库提取。
- 上游配置只从服务端受限文件加载，不进入客户端包；密钥与 access/refresh/id token 不对外记录。
- 回调绑定浏览器与原会话、一次性消费。无密码账号管理依赖近期上游验证证明；解绑保留可用登录方式。
- 第三方实现与配置说明见 upstream-login.md；模板见 upstream-providers.example.json。

## 数据持久化和升级

- SQLite 路径由 AUTH_SQLITE_PATH 指定，容器默认 /app/data/auth.sqlite。
- 迁移台账为 __astra_auth_migrations。bootstrap 执行待登记迁移前先检查完整性并通过 VACUUM INTO 备份。
- 保持 User.passwordHash 与历史 AuthAccount.password 的兼容读取和密码写入策略。
- 新结构采用扩展、兼容、回填、切换、收缩流程；回滚窗口内保留上一版本需要的字段。
- 真实数据库、用户、客户端授权、OIDC 签名密钥及配置应持续保留，不以新建空库替代升级。
- 运行时已有的兼容性结构检查予以保留；新增迁移进入版本化 bootstrap 台账。

## 生产发布

- 本仓库独立构建，不依赖 AstraOS checkout。运行实例切换镜像是独立的发布操作。
- 发布前备份并验证 Auth SQLite、OIDC 签名密钥与部署配置；使用固定提交镜像标签。
- 保持既有公开 issuer、用户 ID、客户端 ID/授权和 cookie 设置。单纯移动源代码不触发账号迁移。
- 保留旧镜像回滚路径；对登录、回调、拒绝未授权用户和授权撤销执行验收。
- 接入方显式预置的应急访问配置由其自身维护，不因本仓库迁移改变绑定主体、有效期或撤销机制。
